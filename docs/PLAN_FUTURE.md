# Deep Learning によるフィラメント電流位置探索の高速化

## Context

C-MAP の収束ループ (`solver.py:154-408`) は、フィラメント電流位置 `(ikr, ikz)` を座標降下法（3方向試行 → 良い方向に進む）で探索している。各試行ごとに磁力線追跡 + Green関数縮約 + Bz誤差評価のフルパイプラインが必要で、100〜1000回の反復が走る。この「数打てば当たる」探索を、Deep Learning で効率化する。

## 改善アプローチ（3段階）

### Phase A: NN による初期推定の改善（最優先・最も費用対効果が高い）

**概要**: 実験入力から最適な `(ikr, ikz)` を直接予測する NN を訓練し、座標探索の初期値を大幅に改善する。

**なぜ効果的か**:
- 入力は低次元（Bz 12点 + コイル電流 ~15変数 = ~28特徴量）、出力は2値 (ikr, ikz)
- 既存ソルバーの実行ログから訓練データを生成できる
- ソルバー自体は変更不要 — 初期値が良くなるだけで収束が 10-50 回に短縮

**アーキテクチャ**:
```
入力:  [bz_puc(12), I_pf_c(11), I_tor_def(1), I_inj(3), t_ana(1)] = 28 features
隠れ層: FC 128×3-4層, ReLU
出力:  [ikr, ikz] (連続値 → 推論時に丸め)
```

**実装ステップ**:
1. `cmaplib/data_collector.py` — ソルバーに訓練データ記録フックを追加
2. `generate_training_data.py` — 複数ショット/時刻でソルバーを走らせ、最良 (ikr, ikz) と入力パラメータを HDF5 に保存
3. `cmaplib/nn_predictor.py` — PyTorch で FilamentPredictor モデルを定義
4. `train_nn.py` — 訓練スクリプト（MSE損失、2-3グリッドセル以内の精度を目標）
5. `preparation.py` を修正 — `ikr0, ikz0` の計算を NN 予測で置き換えるオプションを追加
6. `main.py` に `use_nn=True` フラグを追加

### Phase B: NN 順モデルで勾配ベース最適化（中期）

**概要**: `(ikr, ikz, コイル電流) → Bz(12点)` の写像を NN で近似し、勾配降下で最適位置を求める。

**なぜ効果的か**:
- 現在の各反復は磁力線追跡 + einsum 縮約で数秒かかる → NN forward pass は μs オーダー
- 勾配情報が使えるので座標降下より遥かに効率的
- 訓練済みなら 3.4GB Green関数テンソルが推論時に不要になる

**実装ステップ**:
1. フォワード評価を独立関数として切り出し、(ikr, ikz) を粗いグリッドでサンプリング → 10k-100k サンプル生成
2. FC 256×4層の NN を訓練（入力 ~25、出力 12 Bz値）
3. `solver.py` の座標探索ループ (L286-321) を、NN を通した `torch.optim.Adam` による最適化に置き換え
4. NN 最適化後、最終値で既存ソルバーを 5-10 回走らせて精密化

### Phase C: PINN による全場再構成（長期）

Grad-Shafranov 方程式を物理制約とした PINN/DeepONet で、実験観測から直接 ψ(R,Z) 全体を予測する。Phase A/B が 90% の高速化を 10% の労力で達成するため、後回し。

## 検証方法

1. NN なし vs あり で sq_error（Bz ミスマッチ）を比較
2. 収束までの反復回数を比較
3. 異なるショット・時刻でのクロスバリデーション
4. 物理的検証: 最終 ψ(R,Z) が `sum(I_tor) ≈ I_tor_def` を満たすか確認

## 実装順序

**まず Phase A のみ実装する。** 最小限の変更で最大の効果が得られ、既存ソルバーのフォールバックも保てる。
